# Dashwheel — UX/UI review from the running product (2026-09-26)

The two earlier reviews (`REVUE_UI_UX.md`, `REVIEW_PERF_UX.md`) were done from the source and
their fixes have shipped: 14 sp floor, 48 dp targets, drive lock, OBD pill, day/night, settings
screen, theme gallery. This pass was done differently: the current `main` (83646b4) was built,
installed as the home app on a 1280×720 / 160 dpi Android 10 emulator and **used** — fresh
install, every page, every menu, Settings, edit mode, templates, the widget picker, demo mode,
dark and light, and the Orbit / Cockpit / Tape Deck skins. Screenshots are in
`docs/ux-review-2026-09-26/`. Everything below was seen on screen; where the emulator may differ
from the head unit it says so.

The short version: the pieces are good, the **product journey is not**. A new user meets a wall
of permission prompts, a permanent update banner, a menu that shifts the whole screen, and a
page system named by position. The polish went into tiles and skins; the glue between them is
where the UX still feels unfinished.

Legend: 🔴 blocks or misleads the driver · 🟠 costs time or attention · 🟡 polish / consistency.
Effort: S = hours, M = a day or two, L = a project.

---

## 1. What works (keep it)

- **The standard look, once fed with data, is genuinely good** (`21_demo_right.png`): calm
  cards, one accent, all-caps tracked headers, big numerals, three-state OBD pill. The
  Telemetry, Fault codes and Doors tiles read at a glance.
- **Directions tile**: turn glyph + distance + street, ETA chips underneath. Exactly right.
- **Settings screen**: two columns, one level deep, plain-language rows with a one-line
  explanation each (`08b_settings_look.png`). Best screen in the app.
- **Demo mode** with a loud "made-up data" badge and a Stop right on it.
- **Drive lock** menu rows greyed with a "Park to make changes" line.
- **Edit bar copy**: "Arranging Home — hold a tile to move it, drag its corner to resize it."
- Skins are ambitious and each has a real identity (Cockpit's LCD + chrome, Tape Deck's
  cassette, Orbit's vinyl).

### F. Small things that add up

- **Media tile** in the demo has the progress bar at 0:50 / 3:24 and a play button 70 dp; its art is a pink gradient block. Good size. But "Nothing playing / —" uses an em-dash as a value (house style says no).
- **Speed tile header** says "No signal" in the same grey weight as "OBD" when connected; connected state should read stronger, not the same.
- **Quick dial** is empty until contacts are allowed, then shows starred contacts; the "Dialer" link in the header is the only way to call a number.
- The **Notifications tile** shows a bell icon per row even when the row is a Calendar or Messages item that has its own icon.
- The **Fault codes** card's AI advice runs to three lines and clips ("AI advice (Gemini): it can be wrong. Confirm with a garage before any…").
- **Weather** refresh is a 24 dp icon at the tile's top-right — the only 24 dp target left on a page.
- Home key ends demo mode (seen once); if intended, the badge should say "Home stops the demo".

## 3. Proposals, in the order to do them

### P0 — the journey (do these first; they change how the app *feels* more than any skin)

**1. A one-time setup, parked, three steps (M).**
On first launch (and from Settings → "Set up again"), a full-screen flow instead of six tiles
begging:

1. *Your car* — the preset (C4 Picasso) with "Yes, that's it / Choose another"; driver's side.
2. *Connect* — one screen that lists what the launcher can use, each with one toggle-style row
   that opens the system page and comes back: Notifications (media + directions + messages),
   Location, Contacts & Calendar, Bluetooth OBD adapter. Show a check when granted.
   Everything optional; "Skip" always visible.
3. *Look* — three cards, not fourteen: Standard, Cockpit, Orbit (the others stay in Settings).

After setup, tiles that still lack access show a quiet grey state and **one** shared "Finish
setting up" pill in the bar (like the OBD pill) that reopens step 2. No more per-tile buttons.

**2. Kill the permanent banner (S).**
Update available → a dot on ⋮ and a row in Settings → Advanced ("Update to v1.0.356").
Dismiss is remembered per version. Downloads happen in the background; the install prompt is
offered once, when parked, as a small dialog: "Update now (30 s) / Later". A driver never sees
a strip about software.

**3. Immersive dialogs and menus (S).**
Give every `Dialog`/`DropdownMenu` window the activity's flags (a `DialogProperties`/
`SecureFlagPolicy` wrapper that calls the same `enableImmersiveFullscreen()` on the dialog's
window on show), or render menus and small dialogs as in-tree overlays like Settings and the
drawer already are. Result: no bar flash, no 48 px jump.

**4. Back that works (S).**
A `BackHandler` stack in `AutomotiveDashboard`: dialog → close; widget/app picker → back to
"Add"; edit mode → Done; drawer → close; Settings → close; otherwise → go to Home page; on Home
→ nothing. Map the learnable steering-wheel Back to the same handler.

**5. Name the pages by what is on them (S).**
Templates already know what a page is for: use it. Default names *Home, Car, Media, Day, Trip,
Tools, Spare* (or per template: Road trip gives *Route, Stops…*). Editable in the edit bar
("Arranging **Car**" becomes a text field on tap). The page chip shows the name in 20 sp and
moves to the **top centre** (never over a tile's hero area), or becomes a thin 4 px accent
segment on the top edge that never overlaps content.

**6. Consistent empty states (S).**
One `EmptyTile(icon, line, action?)` component used everywhere: muted icon, one line of body
text (18 sp), optional single text button in the accent. Placeholder values are "--" in the
value's own type style at 60 % alpha, never grey blocks. The Telemetry gauge draws its arc in
`Muted` with no red zone until it has a reading. Trip starts at the first movement, not at
launch. Vocabulary: *Allow* for permissions, *Connect* for devices, *Open X* for apps.

### P1 — choice architecture

**7. Theme gallery that shows the theme (M).**
Render each card by composing the real bar + speed tile + media tile of that theme into a
`Picture`/bitmap at 0.25 scale, day and night. Skins get their own tile (Orbit's ring, Cockpit's
dial, Tape Deck's cassette). Order: the current theme first, then three recommended, then "All"
collapsed. One label: "Skins", not "Universes".

**8. Widget picker as a full-width sheet (S).**
Three columns, 200 dp cards, icon + name + two-line blurb without truncation, category chips
across the top (Driving / Navigation / Car / Info / Apps) instead of scrolling headers. Search
field when the catalogue passes 30. The "Add to dashboard" fork disappears: the sheet has
tabs *Widgets* / *Apps* / *Windows*, and "split pair" lives under Apps.

**9. Lighter edit mode (S).**
On a tile: only **✕** (top-right) and the **resize handle** (bottom-right). Tap the tile →
a small sheet with Zoom (− 100 % +), Design (gallery), Move to page ▸, Remove. Buttons never
overlap the header row (offset them into the tile's padding, or dim the header while editing).
"Reset page" and "Replace all pages" get an inline confirm ("Reset? · Undo stays available").

**10. Trim the catalogue (M, product decision).**
Keep 14 themes but present them as *3 looks + more*; keep 41 widget designs but group them by
family (Modern / Copper / Signature / Original) with one representative card per family in the
picker. Per-tile zoom goes into the sheet (9) and defaults to a per-page zoom.

### P2 — skins as complete systems

**11. Skin the chrome (M).**
Each skin provides its edit-button style, dialog container and banner colours through the same
`DashSkin` hooks it already uses for the bar. Minimum: dialogs use the skin's card shape/colour,
edit buttons use the skin's accent, the update row (if any) is a bar item not a banner.

**12. Cockpit and Tape Deck at 14 sp (S).**
The LCD/monospace lines go to 14 sp (Cockpit's turn line to 18 sp, single line, ellipsis at the
end). One speed readout per dial: needle **or** chip.

**13. Orbit's bar to the driver's side (S).**
Anchor the pill at the bar's driver end (right for LHD, mirrored for RHD, the app already knows
the driver's side) with 48 dp icons; centre only the clock.

**14. One vocabulary across skins (S).**
"No signal" / "No access" / "Waiting for GPS" / "Nothing playing" become the same four strings
in every skin, only typeset differently.

### Hands-free (fits the "tapping is a hassle" rule)

- **Setup and update prompts are spoken once** when parked and the engine is on ("Dashwheel can
  show your messages. Allow it on the screen when you like.") and then stay quiet.
- **Page by voice/wheel**: the learnable wheel actions get *Next page / Previous page / Home*, and
  the page chip is spoken ("Car") when a wheel button turns the page.
- **Auto page**: when navigation starts, go to the page with Directions; when a call comes in,
  stay; when OBD reports a fault, flash the Car page once (setting: on/off).

## 4. What to verify on the head unit

  forced; note whether the layout shifts.
- C3 (Back): hardware Back in Settings, the drawer and edit mode.

  page, and does the tile refresh without a relaunch?

## 5. Emulator method (repeatable)

Twin AVD `HeadUnit_UX` (API 29, 1280×720, 160 dpi) on port 5580, app set as home with
`cmd package set-home-activity`, driven with `scratchpad/ui.py` (tap by accessibility label,
screenshot). `uiautomator dump` does not see popup menus; the bottom bar's controls report empty
bounds (C5). The MapLibre tile shows its emulator placeholder, so the Home page's map area was
not reviewed here.
